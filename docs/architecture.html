🧊 Igloo Platform

Architecture Overview

Serverless dev workspaces that sleep to $0 and wake in ~15 seconds — with persistent EBS disks, browser terminal, VS Code, and SSH.

Section 03
Provisioning Pipeline
Every workspace operation (start / stop / delete) is a job in DynamoDB. Ten concurrent workers claim jobs atomically and run Terraform — no single point of serialization.

DELETE /workspace

📋

🏗️

init (provider cached)

✅
Done
DynamoDB updated
3 retries on fail
Permanent fail → error status
Retry Logic
Max 3 retries per job. Stale jobs (running >15 min after server crash) are re-queued automatically on startup.
In-flight Lock
Per-workspace sync.Map prevents two workers from running Terraform against the same workspace simultaneously.
Delete Guard
Status deleting skips any pending start/stop jobs. Workspace removed from DB only after destroy succeeds.
Section 04
Sleep / Wake Lifecycle
Workspaces auto-sleep to $0 when idle. Your files live on an EBS volume that stays attached — wake time is ~15 seconds, not minutes.
→
Running
Active workspace
Fargate task running (desired=1)
igloo-agent WebSocket connected
sshd listening on port 22
code-server on port 13131
EBS volume mounted at /workspace
~$0.02 / hour
→
Sleeping
Container gone, data safe
Terraform apply with desired_count=0
ECS service scales to zero tasks
EBS detached but NOT deleted
Agent disconnects → status sleeping
DynamoDB record preserved
~$0.001 / hour (EBS only)
→
Waking
Terraform re-provisions
Provisioner claims JobStart from queue
terraform init (provider pre-baked)
terraform apply desired_count=1
ECS starts task with same EBS volume
Agent dials back → status running
~15 second wake time
Deleting
Permanent teardown
Status set to deleting immediately
Start/stop jobs skipped
terraform destroy — ECS service + EBS
DynamoDB record deleted on success
S3 Terraform state key removed
$0 after completion

Section 06
Tech Stack
Minimal, no-framework choices. The whole control plane is a single Go binary under 20MB.
🐹
Go 1.24
API server, provisioner, agent, CLI — single language across all binaries
🏗️
Terraform
Workspace lifecycle. Pre-baked AWS provider in provisioner image. S3 remote state per workspace.
🌐
gorilla/websocket
Agent WebSocket, browser relay, SSH tunnel, VS Code proxy — all over a single WS connection per workspace
🗄️
DynamoDB
Atomic job claiming (ConditionExpression). Store interface is swappable for Firestore / Cosmos DB.
🐧
Ubuntu 24.04
Workspace image with build tools, Python, Node, AWS CLI, code-server, sshd, igloo-agent
🔐
JWT (HMAC-256)
Short-lived tokens for agent, browser, terminal, forward, and VS Code proxy — role-scoped claims
⚖️
AWS ALB
Single entry point. WebSocket sticky sessions not needed — relay is in-memory, one server instance.
🪣
S3 + EBS
S3 for Terraform state isolation. EBS for persistent workspace disk — survives container restarts.

Section 08
EKS Migration Path
The architecture is designed for multi-cloud from the start. Migrating workspaces to EKS is additive — no rewrites required.
✅ Already Agnostic
igloo-agent — just a binary, runs anywhere
WebSocket relay — no ECS dependency
DynamoDB store — behind a Go interface
Job queue — provider-agnostic, dispatches by ws.Provider
Terraform provisioner — runs any .tf files
🔧 What Needs Adding for EKS
New template: templates/aws-eks/ — K8s Deployment + PVC
aws-eks case in worker dispatch → launchEKS()
New env vars: IGLOO_EKS_CLUSTER, IGLOO_K8S_NAMESPACE
Sleep = scale Deployment to 0 replicas (same Terraform, different vars)
Same agent, same relay, same SSH/terminal/VS Code flows
